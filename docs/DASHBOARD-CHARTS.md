# 大屏图表用途与实现顺序

2026-11-14：根据用户提供的 ECharts 示例整理。本文是设计与数据接口建议，尚未实现新图表；不更换已确认的整体视觉，不使用随机数据填图。

## 共同原则

每张图都回答一个业务问题，能定位到相同口径的信息列表。主屏保留管理台、退出、全屏三个顶栏操作，不新增显示设置下拉。颜色统一使用现有设计体系，颜色之外提供文本、数量、图例。大屏用于观察，点击图表可打开只读明细；分配、改派、确认等写操作在管理台进行，展示令牌不能获得未脱敏数据。

所有时间窗、统计单位、去重口径明确。当前系统按规范化网址去重，所以只能称为“信息条数”；同项目多个网址未合并之前不能称为“独立商机项目数”。区域、类别、人员都不得从空值虚构。搜索中追加的省份不是客户所在地证据。

## 1. 地区分配地图（优先）

业务问题：需求信息集中在哪里，哪里尚未分配，哪里分配后无人接收。

默认城市聚合气泡：面积而非半径与信息条数成正比；地名与计数直接显示。全国视图不展示大量公司精确坐标，已确认省份但没有城市时只进入省级聚合，未知地区保留独立计数。项目实施地优先；只有公司所在地时记录其不同地理口径，不混算。注册地址、总部地址不能直接作为项目实施地。

支持直接点击图例中的“全部 / 待分配 / 待接收 / 跟进中”过滤，单时刻展示一种分布。未接收视图可按等待时长着色，阈值由业务配置，无阈值时只显示实际等待时间。不能把不同数量与比例混用同一色标。配套地区排行，避免大面积省份在视觉上夸大数量。

点城市打开对应信息表，列：需求摘要、地区及依据、原始链接、负责人、分配时间、接收时间、状态。推送成功不能直接写为人员已接收。管理员可由明细进入分配管理；地图点击本身不分配。

依赖：信息的结构化地区/依据/地理口径、人员与分配记录、显式接收事件。当前这些尚未完整实现，不能从原始文本模糊命中或推送日志伪造分配地图。

## 2. 新增信息堆叠面积图（优先）

参考 https://echarts.apache.org/examples/en/editor.html?c=area-stack-gradient

业务问题：最近新增是否持续，各类来源贡献是否变化，某来源是否突然停止产出。

横轴时间，纵轴每时间桶首次入库的唯一信息条数；按互斥来源类别堆叠。SearXNG 是发现工具而不是招聘/招采/自媒体类别，未分类结果保留“其他/未分类”。分类未完成阶段可以按采集服务作图，但标题必须表明“搜索服务来源”，不能冒充业务来源。

累计采集与累计入库是重叠集合，不能作为堆叠分项相加；如保留这两项，应采用独立折线。点击某时间段/来源打开其新增信息。无产出不自动等于来源故障，应结合请求错误与重复率判断。

依赖：首次入库时间、去重身份已具备；业务类别需补齐。图表可以先基于现有事件做真实增量统计。

## 3. 分配负荷气泡图（二期）

参考 https://echarts.apache.org/examples/en/editor.html?c=scatter-aqi-color

业务问题：谁手上积压多，是否需要改派。

每点代表人员或团队；横轴未完成信息数，纵轴已分配但未接收信息的最长等待时长，气泡面积表示所选期间新增分配数。没有待接收项时等待为0，并明确显示；颜色可表示团队，不使用AI虚构商机评分。标签至少保留异常/选中人员名称，并提供排序表作为等价入口。

右上方提示查看积压，而非自动判定员工效率：人员工作时段、休假、信息难度会影响指标。点击进入该人员任务列表，管理员人工决定改派。需要分配/接收/跟进记录，不先画样例人员。

## 4. 客户关系图（二期）

参考 https://echarts.apache.org/examples/en/editor.html?c=graph-webkit-dep

业务问题：围绕一个客户，外部新闻、招聘、采购、内部服务与拜访能否连成可核查的信息环。

以选中客户为中心，节点为原始信息、项目、内部服务、负责人员；边必须有明确关系类型和证据。优先显示一至两跳，限制首屏节点数，点击展开，布局稳定不持续乱跳。共同关键词不能直接推断为企业合作关系。

适合客户详情或地图点选后的展开视图，不挤占主屏中心蜘蛛。无CRM时展示已有外部证据关系；CRM接入后增补内部节点。

依赖：企业实体对齐、证据关联与关系类型；当前尚未具备完整关系模型。

## 5. 活跃日历热力图（一期可做）

参考 https://echarts.apache.org/examples/en/editor.html?c=calendar-simple

业务问题：哪些日期有持续新增，哪些日期中断，是否存在长时间空窗。

默认展示最近90天每日首次入库信息量，按Asia/Shanghai自然日统计。点击日期进入当日列表。若运行正常而无新增，显示0；若缺失运行观测，显示“未知/未运行”，不能把两者混成同一深浅。日历中断仅提示排查，不能直接推断市场需求减少。后期可查看接收/跟进事件，但一次只选择一个指标。

依赖：入库时间已具备；运行覆盖状态需调度运行记录补齐。示例里的随机数据生成器不进入产品代码。

## 布局与交付次序

保留当前统一底色、字阶和单只蜘蛛；图表沿用电子青、橙黄、珊瑚粉等现有强调色，渐变限制在图内，避免恢复混色卡片背景。

主屏：顶部为新增趋势与紧凑日历；中间保持来源终端1/3、信息汇集表2/3与蜘蛛搬运；下方为地区地图与地区分配明细。地图细节页承载人员气泡图，客户详情承载关系图，不把全部图缩小塞进一屏。1080p可将地图与采集设为两个同风格视图，默认采集页；具体布局以实际尺寸验收，不牺牲表格可读性。

先完成免费搜索真实闭环，再实现增量趋势与日历；补地区结构化和分配接收最小闭环后实现地图；最后实现负荷气泡与客户关系图。缺数据的图不显示虚构点位或空壳动画。

## 用户最新修正（2026-11-14，覆盖前述第一批图表方案）

第一张不用搜索服务分组，改业务归集/发送口径；颜色与面积处理采用所给原例，发送未接入保持未知。日历保留并增加条数，默认ECharts热力样式；第三张改原例气泡样式表示任务状态/流转时间/尝试次数。省级信息地区地图已先实现，分配口径仍等待人员分配事件，不能冒充完成。来源终端滚动、单只蜘蛛左右移动、信息表标题加两行摘要为明确要求。
