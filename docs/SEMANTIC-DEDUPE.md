# AI 相似商机与监控分流

2026-11-15：来源显示名统一为商机、小红书、监控，内部来源代码保留，不改历史来源身份。

## 监控
已通过客户身份、主题、日期筛选的原文先进入待审核。DeepSeek 判为 buyer_demand 则将 Item 业务类型改为 opportunity，来源仍为监控，进入正常商机推送和认领；判为 customer_news 则继续 customer_update，独立播报，不要求认领。不确定留待核实，无关内容归档。
同一监控原文被再次采集不会把已经提升为商机的记录重置回资讯。分配、消息文案、认领权限、统计和大屏面板都按业务类型分流，不按来源强制排除监控。

## 去重
1. 规范化相同正文仍用指纹直接去重，保留补充来源网址，节约模型费用。
2. AI 商机审核通过后，在近30天、最近400条有效商机中，用标题三字片段、项目编号和同网址找最多5条候选。仅是粗检索，不是合并依据；这不是全库穷尽或向量检索。
3. 有候选才调用 DeepSeek 比对。只传候选标题及原文，不传账号凭证。分类结果缓存，若比对失败，重试不重复做分类。
4. duplicate：新记录标 merged，关联原商机，保留原文与网址；不进入重复推送。原商机来源网址列表追加新网址。
5. update：保留独立有效记录，关联原商机，标新进展，允许正常推送；distinct：独立信息；uncertain：待核实，不自动合并或放行。
6. 合并/更新必须返回候选中的真实 ID，且两份原文均有可逐字校验的证据。程序不会物理删除原文或历史推送/认领。
7. 单独的审核锁串行化最终准入，防止两个同时审核的相同新项目互相漏看；不锁采集、通知队列。比对原文超40000字符或单条超16000字符时待核实。

后台信息库新增“重复信息（已合并）”，详情展示AI比对理由、关联商机与补充来源网址。保持表格紧凑，详细信息在详情查看。

## 边界
模型判断仍可能误判；有意保持不确定状态，不声称零重复。候选检索可能漏掉改写很大的同一事件。
本次不将已通过的历史商机全部下架重审；新候选按新流程处理。模型技术失败的记录仍可在后台重新审核。
网站同一 URL 的正文变化，在普通商机采集收到新正文时会保留新版本供审核；监控来源沿用既有每客户 URL 的采集去重，当前不自动追踪同 URL 新闻改版。
