# 0.1 实现与验证记录

## 已完成

- PostgreSQL 迁移：规则、任务、尝试记录、任务 Outbox、原文版本、信息条目、持久化事件。
- 任务仅携带 ID 入 Redis；数据库先提交，独立调度器再投递。未确认执行的消息每 30 秒重新投递，消费者通过锁和租约令牌防重复写入。
- Worker 有限重试、授权等待、超时租约回收；不同来源结果使用独立子任务。
- Tavily 搜索适配器和独立演示适配器；原文留存、正文/摘要区分、精确去重、邮箱与大陆手机号候选提取。
- 规则创建/启停/手动运行、任务查询/重试、证据详情、信息列表 API；管理员/脱敏展示令牌隔离。
- React 管理台与石墨灰大屏；图表读取数据库统计，SSE 重连加快照校正，新增信息触发蜘蛛搬运。首次打开不虚构历史动画。
- 分配与通知区域显示尚未接入，不用演示回执充当真实功能。

## 连续采集与运行反馈 · 2026-11-14

根据用户纠正，interval_seconds=0表示连续模式：当前批次的搜索与入库完成后，由常驻调度器下一次检查接续下一批（调度检查约3秒），不设4小时等待或30秒人为冷却。失败保留有限重试及服务授权/额度等待，不将失败伪装成功。停止不再创建下一批，当前批次允许完成。

关键词按每行一组轮转，逐组扩展预设地区；一轮组合穷尽后会重新轮转，可能返回重复结果并由现有精确去重合并。尚未实现站内链接发现、搜索引擎分页、跨域语义去重或自动构建无限搜索空间；不能宣称“全网抓完”。单次Tavily请求最多20条是供应商接口约束，不是总采集数量上限。界面移除该批次参数、演示/真实标记与下拉；保留管理台、退出、全屏。

大屏新增实际批次、搜索词、状态、清洗进度、重复数；原生progress显示已完成子任务数。蜘蛛在实际搜索/清洗时巡视，无新信息不搬运原文；一次新信息的搬运不会因运行状态变化重复播放。历史演示记录仅留于数据库，不混入正常页面。21项后端测试、生产构建通过；连续实际运行观察到第9批时124条入库，无人工逐次触发。

免费额度耗尽仍需等待供应商恢复或接入其他来源；没有开启付费，没有承诺无限免费。正文噪声与结果相关性仍需后续改进。

### 同网址去重补充

运行时发现同网址的搜索片段变化被旧内容版本策略计为新信息。本轮改为同一规范化网址/数据模式只保留一条信息入口，新写入以网址身份唯一约束防并发重复；历史版本保留在库中，列表、数量与累计归集趋势按网址合并。后续需要单独设计已知网址更新机制，当前不会把同网址新片段作为新信息。跨网址转载与跟踪参数别名仍不属于已实现的去重能力。新增回归测试后共22项通过，并验证运行中列表网址唯一、累计归集曲线末值与信息数一致。

前端将自动刷新连接错误与操作错误分开，恢复连接后自动清除过期断线提示。
