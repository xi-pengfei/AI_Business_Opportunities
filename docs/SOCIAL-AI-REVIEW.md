# 商机 AI 准入审核

2026-11-15：接入 DeepSeek，独立 ai-reviewer 容器。已扩大到所有 opportunity/demand 商机候选，按业务类型审核，不限制来源。客户监测的 customer_update 资讯不属于商机，维持独立播报。

流程：读取原文 → 日期/正文完整性检查 → 原文及候选落库（review_pending） → DeepSeek 判断 → buyer_demand 才进入有效信息库、来源终端、蜘蛛搬运与既有钉钉认领流程。

模型分辨买方需求、服务商营销、教程、招聘、无关和不确定。预算和公司实名不是必需条件。通过必须包含能在正文逐字找到的证据，仍需业务人员核实，不宣称 AI 保证准确。

- 本地 .env：DEEPSEEK_API_KEY、DEEPSEEK_MODEL（默认 deepseek-flash）。仅后端读取，不提交、不打包。
- 正文作为不可信数据传给模型；不执行其中指令。仅传标题和正文，不传账号、Cookie 或钉钉凭证。
- 单篇正文最多16000字、输出最多600 tokens；超过长度待核实，不截断后贸然放行。
- 无密钥：保持待审核，不放行。超时、接口错误、非法 JSON、无原文证据：有限重试3次，之后待核实。不会降级成关键词自动放行。
- 管理台 → 信息库 → 信息状态：待 AI 审核、待核实/审核异常、已过滤/已归档。详情展示理由及依据；待核实可重新审核。
- ai-reviewer 每10秒处理一条；请求超时35秒。记录模型、提示词版本、时间和证据。独立队列故障不影响其他来源。
- 审核通过以审核时间进入大屏增量流，采集时间仍保留原值；无审核通过的新记录时不伪造蜘蛛搬运。
- 普通关键词仍承担日期、完整性等清洗；新鲜小红书正文不再仅凭正则判断买卖方；网络招采经规则初筛的候选同样必须通过 AI 才能成为有效商机。
- 迁移 m013 将现有 active 小红书候选置为待审核；保留原文和已有发送记录，不撤回群消息。

实际验证：现有两条“AI智能体定制开发，让Agent参与业务”“小红书笔记”均被模型判为 seller_promotion 并归档，查询时无钉钉发送记录。

修改密钥或模型后：docker compose up -d --no-deps ai-reviewer
排查：docker compose logs --tail=50 ai-reviewer（日志不输出请求正文、密钥和接口响应体）。
模型调用为付费 API，按服务商实际用量计费；未设置自动充值。


## 2026-11-15 全来源扩展
迁移 n014 将现有未获 AI 通过的有效商机转为待审核（含已推送/已认领，发送和认领历史保留不删除，不重新发送）。
统一列表查询、有效信息库、大屏增量和商机推送都要求 buyer_demand；脚本误置 active 也不能绕过门槛。
