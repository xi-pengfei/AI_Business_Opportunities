# 信息时效与分流（2026-11-15）

- 业务库仅接受来源日期在近 30 天内（上海自然日）的信息。搜索端 month 只是提示，清洗端再次校验。未来日期、无法核实发布时间、超过 30 天的内容归档，不用采集时间冒充发布时间。
- 原始证据、归档原因、推送与认领历史保留。管理 API `/api/v1/items?status=archived` 可分页查询归档，详情仍包含原始证据。
- 调度器每 60 秒检查一次：未认领信息采集满 30×24 小时、或来源日期已超 30 天自动归档。检查失败不阻断采集；下次重试。通知筛选另有时间边界检查。
- 已认领的工作不因采集满月被自动放弃；重新整理时发现原信息已过期仍可退出活跃展示，但人员、认领及推送记录不变。
- 已推送待认领的信息归档后不再阻塞下一条。发送结果未知仍保持安全暂停，不因归档重发。
- 同一规范网址（去追踪参数与锚点、查询参数排序），或清洗后完全相同正文视为重复。PostgreSQL 事务锁防止跨网址相同正文并发写入。重复不刷新日期、不产生新增动画。不同措辞的语义重复尚不自动合并。
- 政策、报道、一般招聘及缺乏明确需求证据的信息归入 bulletin，不推送、不计商机积压。主体与需求语句均存在才作为 opportunity 候选；这是可审查的保守规则，不替代人工核实，也不以政府域名一刀切。
- `python -m scout.reprocess` 重整全部历史派生记录，保留原始文档，支持重复运行。不会伪造新采集事件。
- 大屏 API 提供独立 `bulletins` 列表。左右 2:1 新闻区的前端布局尚未部署；本次不覆盖另一 agent 正在修改的蜘蛛与页面文件。
