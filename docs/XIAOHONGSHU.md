# 小红书需求采集

## 用户操作

1. 在管理台打开“小红书”。
2. 点击“扫码登录”，用小红书App扫描二维码，并在手机上确认。不要把密码或Cookie粘贴到系统里。
3. 页面确认登录后，已启用的关键词任务自动继续。可修改关键词，每行一组，保存即持续采集；点击停止只停止后续批次。
4. 有效需求依次出现在大屏来源终端、蜘蛛搬运和信息库。客户动态仍是独立区域。小红书需求暂不自动推送钉钉。

连续运行是后台轮换关键词、处理本批并周期复查，不是持续高频刷新同一个页面。小红书每批间隔至少60秒；遇到连接失败冷却10分钟，登录失效/验证暂停该账号，其他来源继续。没有金额或正式公司名称也可以保留，但必须能在原文看到需求表达。保留近30天，未知日期归档，帖子ID与内容去重。图片里的文字、视频语音、评论需求尚未识别。

## 接入与部署

使用开源 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 的 HTTP 接口。它是第三方连接器，不是小红书官方数据API。程序只允许调用登录检查、扫码、搜索、笔记详情四类接口；不调用发布、评论、点赞、私信和关注。

```sh
# .env 设置随机 XIAOHONGSHU_TOKEN；不是小红书密码。
docker compose --profile xiaohongshu up -d xiaohongshu social-worker
```

连接器只在Compose内部网络提供服务，无对外端口。`XIAOHONGSHU_TOKEN`用于内部接口认证；Cookie在独立Docker卷 `xhs_session`，不会进入Git、任务队列、API返回或前端。`note_token`是搜索结果里的单篇公开笔记访问参数，不是账号Cookie，详情读取完成即从任务载荷移除；信息库只返回不含访问参数的原始帖子网址。

接口版本按部署镜像锁定。源项目提示同一账号在其他网页端重新登录可能使现有会话失效。持续采集依赖平台可访问性，不能保证免限流或不触发验证，也不绕过验证码、访问限制或登录权限。

## 数据和展示

`Rule.source_type=social_demand`，`provider=xiaohongshu`，独立`social`队列、单Worker。搜索得到帖子ID后，每帖独立读取正文、原始发布日期，成功后复用清洗、Item、事件和大屏feed。不会把搜索卡片的标题当作完整正文。

`Item.source_type=social_demand`、`information_kind=demand`、`category=小红书需求`。公开招采的历史拒绝指纹不适用于小红书；全网资讯清理也不会删除小红书需求。钉钉明确仅选择opportunity类型，需求先进入信息库供人工查看。

搜索接口目前返回页面已加载的结果，没有已验证的分页游标；首版轮换关键词并按最新排序复查，不宣称可以无限翻页或搜全所有帖子。没有返回正文、登录异常、验证码、响应格式改变都不视为正常空结果。采集动画仅由真实新增Item触发；测试数据只用于隔离测试，不进入生产库。
